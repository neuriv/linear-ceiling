Selections and measurements

How the experiments were set up

Each run changes a defined part of cache use and measures a specific outcome. The code in the repository is the executable record; this page explains what it does.

Short cache replacement

The eight initial cases are the first eight handoffs in sorted archive order. The script takes 256-token sender and receiver windows around the first shared token whose source and destination positions differ, then keeps only tokens matched in both windows. In this first run, 12 prefix positions were replaced per case. The higher-coverage run selects eight evenly spaced handoffs from the 25 scored E9 cases and takes the first matched block of at least 128 tokens beginning at receiver position 32 or later. Windows are centered 128 tokens before that block.

For each receiver, the script computes a fresh cache. It then replaces matching prefix keys and values with sender values. Keys are rotated to the receiver’s positions; values are copied directly. Unmatched positions stay fresh. A position-permuted replacement is the disruption control. The comparison reads next-token logits at the same final receiver token.

Reuse across model checkpoints

The same eight excerpts are decoded with the OLMo tokenizer and capped at 256 tokens. Writer/reader pairs are 200→1200, 200→2600, and 1200→2600. In each pair, the reader weights, token IDs, and positions are fixed; the cache was written by a different checkpoint. The script compares per-token key and value errors after removing key positional rotation, next-token probabilities, and greedy continuations of exactly 32 tokens. Same-checkpoint continuation controls use step 1200.

Math-answer scoring

NumPy seed 230923 selects 64 test questions and, separately, eight training demonstrations from GSM8K. The OLMo step-2600 reader receives identical token IDs in both arms. The fresh arm uses a step-2600 cache; the reuse arm uses a step-200 cache. Greedy generation stops at EOS or 384 tokens. The score extracts the last #### number when present, otherwise the final number, and checks exact numeric equality. Truncation and missing answer markers are recorded separately. Questions with changed fresh/reused correctness are regenerated in MPS float32 as a sensitivity check.

Context scaling and added history

The four shortest included E9 handoffs are tested at native position settings and YaRN scaling by 2.5, with the original history or a repeated 4,096-token shared prefix added to both prompts. The focal sender and receiver text stays the same. The same 512 evenly spaced matched positions are compared in every cell. Each cell’s own positional rotation and amplitude are removed before measuring key error. Error is normalized by the native/original receiver’s per-head variance, held fixed across the four cells.

The added prefix changes both earlier shared content and the positions of the focal tokens. The comparison therefore measures the combined effect of those changes under each positional setting.

Complete-history reuse and timing

The three shortest included handoffs are wrapped in the same evaluation prompt and processed as complete histories. The fresh arm recomputes the receiver. The block arm copies aligned runs of at least 32 tokens and computes every gap using the cache assembled so far; it processes the final prompt token. The prefix arm reuses only the exact shared leading text. A scrambled-block arm changes order as a control. Timing includes alignment, position correction, cache assembly, gaps, and question processing, while the source cache is assumed to exist. Source-cache build time is recorded separately.

Eight objective questions ask for repository, function, or class names found in the history. These measure exact retrieval from the history, not code-fix performance.

Archived record review

The audit loads archived score and per-token files at fixed E9, E9-scaled, and E9-long revisions. It checks each file’s archived SHA-256, divides each token’s squared key error by the archived per-head centered variance, and averages over layers and heads. It recomputes f* by removing the largest errors until the remaining average meets the threshold. It also counts individual token errors above that threshold. The refutations page explains why these are different questions.

Original model outputs and intermediate caches were deleted after the first reporting pass. These specifications and source revisions allow fresh runs with the same selection rules.
