# Long-Qwen cache readout: proposed descriptive run

Status: reviewed code and offline tests; no long-cohort GPU measurements or new verdict.
The fork execution is frozen in [this record](2026-10-01-cache-behavior-freeze.json).
Upstream ledger admission remains separate.
This is a small extension of the cache-injection pilot at
`neuriv/cache-injection@8e8417a6a6186d4a4164c3477836e25892fdf046`.
It does not change the registered E7/E8/E9 drivers or their findings.

## Question and scope

On the original 35 E9-long Qwen3-1.7B handoffs, how much does actually reading reused
KV change next-token predictions along the recorded continuation? The text was
generated by the original proprietary receiver. KL and top-1 agreement measure
prediction sensitivity on that fixed text, not task success or free-generation quality.
No HOLDS/DEGRADES thresholds are assigned to these new measures.

Use exactly the archived `pairs`, including one-token matches. Assemble the entire
receiver cache. Compute each unmatched or selected-for-recompute gap against the
already assembled cache. The first continuation token is shared conditioning text;
it is unscored. Predictions after `C[:-1]` are compared for `C[1:]`. This avoids
silently recomputing a matched final receiver token to obtain its output logits.

Default arms are fresh, reused, a norm-matched random null, and a cyclic permutation
of matched source states. The null preserves the K and V perturbation norm separately
at every token, layer, and KV head. It tests perturbation direction; it is not a
quality threshold. Optional `oracle_fractions` select the largest archived mean key
deviations and recompute those tokens in order. These are **oracle-ranked** arms,
not CacheBlend and not an attainable repair-cost bound. They are disabled by default. The stored numeric fraction drives selection directly;
labels do not round the budget. Duplicate labels and out-of-range fractions are refused.

## Correctness and memory

All arms use one pinned Transformers 5.17.0 / PyTorch 2.14.0 runtime, float32, SDPA,
the fixed model revision in the config, and the original static YaRN-2.5 schedule.
The driver sets `CUBLAS_WORKSPACE_CONFIG=:4096:8` before CUDA initialization and
records it; conflicting existing values are refused. TF32 is disabled and PyTorch
deterministic algorithms are enabled. Actual GPU numerical controls remain required.
Keys are unrotated at the source position and rotated at the destination, retaining
their existing YaRN amplitude exactly once. A single delta-angle rotation is
mathematically equivalent but suffers additional fp32 phase rounding at long positions.
Moving between different rotary schedules is unsupported by this experiment.

The largest handoff is scored first as the memory probe, then retained for the full
run. Repeating a completed probe verifies that result without scoring another handoff.
Its fresh repeat and prefix-copy controls must fall within the declared maximum
logit error. Every handoff also bridges the current runtime's same-model centered
K/V mean deviation to its archived E9 value. These are numerical correctness checks,
not behavioral acceptance thresholds. Changing their tolerances after observing a
failure requires a new configuration and a documented reason; no silent relaxation.

Start with **one L40S 48 GB, A100 80 GB, or H100 80 GB**. The earlier full sender
prefill peaked at 31.56 GiB; 40 GB is marginal until this implementation's real probe
passes. Only matched sender states and fresh receiver states are retained on CPU;
the full sender GPU cache is freed before candidate assembly. CUDA timing synchronizes
explicitly. The probe reports measured peak allocation; speedup is not an outcome.

## Attention diagnostic

The observer reconstructs fresh causal attention from the actual SDPA forward's
normalized queries and cached keys. It never replaces the model's attention output.
Query heads use their corresponding grouped KV heads. Scores are reduced in small
query chunks, so no full prompt-square attention matrix is retained.

The default covers the **last 32 receiver query positions** at every layer/head.
It records attention-weighted archived key deviation and attention mass on tokens
whose original mean-over-layers/heads deviation exceeds the tolerance. The tail set
therefore matches the paper's token-level definition. This is a bounded slice of E-TAIL Part B, not the
proposed all-query experiment or a proof of behavioral preservation. The archived
error values and newly observed attention remain distinct measurements. Large
attention-weighted errors suggest a possible mechanism; they do not establish causation.
Matched-token attention mass and weighted deviation conditional on that mass are
reported alongside. The conditional quantity is explicitly undefined at zero matched
mass, with the number of undefined observations reported. This distinguishes small
errors on attended matched tokens from simply attending elsewhere.

## Commands and records

The user supplied the H100 before the fork execution record was committed. This
descriptive follow-up therefore does not claim upstream R1 registration or a new
registered verdict. Its code, inputs, controls and stopping rule are frozen before
long-cohort inference. Upstream ledger admission remains the operator's decision.
Use the pinned experiment environment; do not upgrade it during a run. Model/tokenizer files must
already be downloaded at the pinned revision; these commands are offline by default.
On a new machine, install once with `python -m pip install -e . -r
tools/cache_behavior/requirements.txt` using Python 3.12, then run the offline tests.

```bash
python -m pytest -q tests/test_cache_behavior.py
python -m tools.cache_behavior.run --prepare --inputs results/cache-behavior/inputs \
  --archive /path/to/verified/e9l --traces /path/to/traces \
  --evidence-sha256 /path/to/evidence/SHA256SUMS
python -m tools.cache_behavior.run --check --inputs results/cache-behavior/inputs
python -m tools.cache_behavior.run --probe --inputs results/cache-behavior/inputs \
  --output results/cache-behavior/run
python -m tools.cache_behavior.run --run --resume --inputs results/cache-behavior/inputs \
  --output results/cache-behavior/run
python -m tools.cache_behavior.run --summarize --inputs results/cache-behavior/inputs \
  --output results/cache-behavior/run
```

The trace root must contain `swe-bench/<submission>/<instance>.json`. Preparation checks
each trace against the original committed corpus manifest, verifies S/R text and
tokenization against the archive, verifies archive files against the supplied evidence
SHA256SUMS and score/token hashes against the archive report, and
records hashes of each trace, alignment, continuation text, and prepared input. Missing
or very short continuations are counted as exclusions, never replaced by invented text.
Archive input hashes come from its verified local `report.json`; retain that original
report and the corpus manifest with the run's evidence.

After each handoff the driver saves per-token KL/top-1 observations, continuation IDs,
attention summaries by layer/query/head, controls, memory peak, and a hash-checked
checkpoint. On the first/largest handoff it also retains fresh and per-arm vocabulary
logits at the first four scored positions (or all if fewer), with explicit continuation
indices. This witness is under 10 MB for the default arms. The CPU
summarizer independently reproduces those positions' KL and top-1 results before using
the per-token metrics. Resume refuses changed code, config, input manifest, runtime, or GPU type.
Summary and resume also check the cohort against the prepared manifest, require the
scored handoffs to be an exact prefix of its unique run order, and verify that
`complete` is true exactly when every included handoff has been scored.
The CPU summarizer recomputes handoff metrics and cohort median/p10/p90 from those
records using the repository's quantile convention. It rejects missing witness metadata,
truncated token metrics, nonfinite KL, and witnesses covering the wrong continuation positions. It reports completion and exclusions;
an incomplete result is not described as a complete 35-handoff experiment. No bootstrap
or quality verdict is added. Follow the existing pull/verify/backup/release protocol and
retain the verified evidence together under `~/Desktop/Carryover-evidence`.
